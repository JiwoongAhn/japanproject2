# 📱 기기 호환성 & 학교 확장 참고 노트

> "다른 폰/다른 학교에서도 될까?", "확장하려면?" 궁금할 때 여는 문서. (최종 갱신: 2026-07-21)

---

## Q1. 내 폰에선 되는데 다른 폰에선 안 될 수 있나? → **있다**

원인은 3층:

1. **OS 차이 (iOS ↔ Android)** — 가장 큼
   - manaba 로그인 쿠키 유지, 키보드 자동 스크롤, 알림 권한은 iOS/Android 내부 구현이 다름
   - **현재 iOS만 검증됨. Android 키보드·쿠키 미검증** (출시 전 필수)
2. **OS 버전 차이** — iOS 15.1+ 필요. 아주 옛 기기에서 레이아웃/API 차이 가능
3. **화면 크기** — 작은 폰에서 글자 잘림·버튼 겹침 가능

### 확인·수정 방법
- TestFlight로 **다른 iPhone 기종/버전**, Play 내부테스트로 **Android 실기**에 배포 후 직접 테스트
- 재현되면 → 크래시 리포팅 로그 확인 → `Platform.OS === 'android'` 조건 분기로 대응
- 원칙: **"내 폰 1대 = 검증 아님". 최소 iOS 2대 + Android 1대**

## Q3. 다른 폰에서 안 되면 다른 학교는 아예 안 되나? → **원인이 다른 별개 문제**

- **기기(OS) 때문에 안 됨** → 학교와 **무관**, 모든 학교에 동일 영향 (예: Android 키보드)
- **학교(포털) 때문에 안 됨** → 그 **학교만** 문제 (manaba HTML이 학교마다 조금씩 다름)

즉 하나가 안 된다고 다른 게 자동으로 안 되는 건 아님. **기기 문제 ≠ 학교 문제.**

---

## Q4. 다른 학교 확장 시, manaba가 아니면 처음부터 설계? → **아니오 (뼈대 재사용)**

앱의 3대 장점을 학교 의존성으로 분해:

| 장점 | 학교 의존성 | 재설계? |
|---|---|---|
| 학생 전용 커뮤니티 (게시판·수업평가) | **무관** (이메일 도메인만 추가) | ❌ 그대로 |
| 이메일 OTP 로그인 | **무관** | ❌ 도메인만 추가 |
| 재로그인 적음 (쿠키/자격증명 유지) | 구조 재사용 | 🔶 LMS별 적용 |
| 시간표 한 번에 + 교실 자동 | **LMS 의존** (kaede 학습나비 파싱) | 🔶 LMS별 파서 |
| 공지 푸시 | **LMS 의존** (manaba) | 🔶 LMS별 어댑터 |

### 핵심
- 뼈대(인증·커뮤니티·수동 시간표·WebView+파싱 파이프라인·푸시 인프라)는 **전부 재사용**
- 비(非)manaba 학교(WebClass·Blackboard·UNIPA 등)는 **그 LMS용 "파싱 어댑터"만 추가** = 앱 재작성 아님, **학교별 플러그인** 개념
- **현실 난이도**: LMS마다 로그인·HTML이 달라 어댑터 1개당 실측 작업 큼
- **효율적 확장 전략**: **같은 LMS(manaba) 쓰는 학교부터 묶어서** 확장 (파서 재사용률 최고)

### 새 학교 추가 시 최소 작업 (커뮤니티만이라도)
- `src/constants/universities.js`: id·name·emailDomain·campuses·periodRanges
- `src/constants/universityLinks.js`: homepageUrl(필수)·manabaUrl 또는 lmsUrl·syllabusUrl
- → 이것만 해도 **커뮤니티+수동 시간표+수업평가**는 즉시 동작. LMS 연동은 이후 단계.
