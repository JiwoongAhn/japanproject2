# 講義評価 시딩 데이터 (국사관대학)

> 커뮤니티 시딩 트랙 — **DB 미투입 상태**. 확정본이며 SQL 작성 단계만 남음.
> 원칙: **내용은 전부 실제 수강 경험 기반**(사용자 본인 작성 → 일본어 정리).
> 이름만 보고 지어낸 리뷰는 넣지 않는다(실명 교수 명예·앱 신뢰도 문제).

## 시드 계정 설계

| 항목 | 내용 |
|---|---|
| 계정 수 | 8개 (`unione_seed_01` ~ `08`) |
| 이메일 | `seed01@unione.local` 형식 (외부 발송 불가 도메인) |
| university | 전부 `国士舘大学` |
| share_timetable | 전부 `false` (공강맞추기 노출 방지) |
| 계정별 말투 | 01 정중체·긴 글 / 02 캐주얼·솔직 / 03 정중체·담백 / 04 분석형 / 05 밝은 톤 / 06 짧고 깔끔 / 07 だ·である체·직설 / 08 정보 나열형 |

## 제약 (코드 확인 완료)

- `course_reviews.tags`: 태그 1개당 **최대 10자**, 1건당 **최대 8개** (`CourseReviewCreateScreen.js`)
- 앱 추천 태그 10종: `わかりやすい` `出席必須` `課題多め` `テスト重要` `おもしろい` `単位楽` `難しい` `予習必須` `実践的` `おすすめ`
- 그 외는 자유 태그 (위 10자 제한 준수)
- `course_reviews`에 `is_anonymous` 컬럼 **없음** → 앱에서 작성자가 어떻게 표시되는지 DB 투입 전 확인 필요

## 집계

- **총 22건** · 계정별 2~3건 분산
- 별점 분포: ★5 3건 / ★4 7건 / ★3 9건 / ★2 3건
- ★2 3건은 `seed_02` `seed_03` `seed_07`에 분산 (한 계정이 불평만 하는 인상 방지)
- 작성일: 2026-07-22 ~ 09-24 분산
- 교수명 없는 11건(과거 학기)은 `professor_name = NULL` — 익명성에도 유리

## 남은 작업

1. `course_reviews` 작성자 표시 방식 확인 (`is_anonymous` 컬럼 없음 → 닉네임 노출 여부)
2. 시드 계정 8개 생성 → UUID를 `docs/seed-accounts.md`에 기록
3. `docs/seed-community.sql` 작성 (트랜잭션으로 묶기)
4. 되돌리기: `DELETE FROM auth.users WHERE email LIKE '%@unione.local';` (CASCADE로 전부 삭제)
5. 게시판 글 목록 시딩 (별도 트랙 — 사용자가 직접 정리 예정)
